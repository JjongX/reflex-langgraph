API
***

This page describes the application programming interface (API) of reflex-langgraph.

A backend needs only the names the package exports at its top level (``from
reflex_langgraph import ...``); the UI's names are in ``reflex_langgraph.ui``. Below is
the list of submodules:

**Configuration and settings**

- :mod:`config <reflex_langgraph.config>` : The config submodule describes every agent of an app in one YAML file (or dict).
- :mod:`env <reflex_langgraph.env>` : The env submodule reads and creates ``.env`` files: one place for an app's API keys and settings.
- :mod:`policy <reflex_langgraph.policy>` : The policy submodule decides who may see and do what.

**Agents**

- :mod:`agents.builder <reflex_langgraph.agents.builder>` : The builder submodule compiles an :class:`~reflex_langgraph.config.AppConfig` into one LangGraph graph.
- :mod:`agents.tools <reflex_langgraph.agents.tools>` : The tools submodule holds the registry of tools that agent configurations name.
- :mod:`agents.attachments <reflex_langgraph.agents.attachments>` : The attachments submodule shows the model the files users attached to their messages.
- :mod:`agents.blocked <reflex_langgraph.agents.blocked>` : The blocked submodule recognizes replies the model provider blocked, and keeps them out of later model calls.
- :mod:`agents.checkpoint <reflex_langgraph.agents.checkpoint>` : The checkpoint submodule keeps conversations' graph state durable.

**Jobs**

- :mod:`jobs.spec <reflex_langgraph.jobs.spec>` : The spec submodule describes a kind of job: subclass :class:`JobSpec` once per kind of long-running work.
- :mod:`jobs.runner <reflex_langgraph.jobs.runner>` : The runner submodule runs jobs as detached processes, with a concurrency limit, cancel and provenance.
- :mod:`jobs.progress <reflex_langgraph.jobs.progress>` : The progress submodule turns a job's log into step-by-step progress.
- :mod:`jobs.tools <reflex_langgraph.jobs.tools>` : The tools submodule gives agents tools over a :class:`JobRunner`.
- :mod:`jobs.router <reflex_langgraph.jobs.router>` : The router submodule serves a :class:`JobRunner` over HTTP, for the UI's jobs panel.

**Server**

- :mod:`server.app <reflex_langgraph.server.app>` : The app submodule builds the FastAPI application that serves a graph to the UI.
- :mod:`server.store <reflex_langgraph.server.store>` : The store submodule keeps the server's list of conversations.
- :mod:`files <reflex_langgraph.files>` : The files submodule keeps the files users attach to their messages.
- :mod:`server.stream <reflex_langgraph.server.stream>` : The stream submodule translates a LangGraph run into the events the server streams.
- :mod:`server.events <reflex_langgraph.server.events>` : The events submodule defines the events a run streams from the server to the UI (SSE).
- :mod:`server.schemas <reflex_langgraph.server.schemas>` : The schemas submodule defines the server's HTTP response bodies.

**UI**

- :mod:`ui.components <reflex_langgraph.ui.components>` : The components submodule builds the page: the conversation list (with rename, delete and search), the chat, approval cards, the approvals queue and the jobs panel, and :func:`agent_page`, which puts them together.
- :mod:`ui.state <reflex_langgraph.ui.state>` : The state submodule holds the Reflex states behind the page: the conversation and its list, the jobs panel, and the approvals queue.
- :mod:`ui.client <reflex_langgraph.ui.client>` : The client submodule is an async client for the server's API, used by the Reflex states and usable on its own.
- :mod:`ui.reducer <reflex_langgraph.ui.reducer>` : The reducer submodule folds the server's events into the items the chat shows.
- :mod:`launcher <reflex_langgraph.launcher>` : The launcher submodule generates and runs the Reflex project behind ``reflex-langgraph ui``.

For getting help on a specific submodule (e.g. jobs.runner):

.. code:: python3

   from reflex_langgraph.jobs import runner
   help(runner)
